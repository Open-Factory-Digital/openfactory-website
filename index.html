Policy authorizes the action. You judge the result.

Interactive AI coding still makes a human approve every step: "yes, yes, yes." OpenFactory inverts that. A cascade of policy (a quality floor, stack presets, org defaults, project rules) authorizes what an agent may do, and a human's job becomes judging outcomes instead: the diff, the gates, an independent review. Not rubber-stamping each action.

It orchestrates coding agents that already exist (Claude Code, Codex, Kimi, OpenCode) behind one contract. It is not a new one. One executor works the ticket end to end in a proven sandbox with the project's own gates, and a second, independent agent reviews the diff before it merges. When it cannot proceed, it doesn't go quiet. It asks a human a concrete question with executable options.

Why teams use it

Ship more, review less

Ships reviewed pull requests, not just diffs

It picks up a ticket, writes the code in its own sandbox, and opens a pull request that a second, independent AI has already reviewed before you ever see it.

Never fails silently

When it can't proceed on its own, it asks a person a concrete question instead of quietly stalling or guessing at an answer.

You keep the keys to production

It can open and merge pull requests, but deploying to production always stays a human, authenticated action. It never gets that key.
